# Smoke baseline 2026-04-25 (multi-doc) — pooled retrieval across two PDFs

Not a full re-baseline. The gold set in `tests/eval/gold.json` is single-paper; building a multi-doc gold is its own project (tracked as an ADR-0005 follow-up). This file captures **two smoke checks** that confirm the multi-doc plumbing from ADR-0008 works end-to-end without dragging single-doc behaviour off.

## Setup

- PDFs: `tests/fixtures/attention_is_all_you_need.pdf` (15 pages, the gold-set fixture) **+** `tests/fixtures/three_pages.pdf` (the synthetic 3-page fixture used as a noise document).
- Embedder: `all-MiniLM-L6-v2` (default).
- Retriever: `DenseRetriever` over the **pooled** passage list (15 + 3 = 18 passages indexed together).
- Answerer: `StubAnswerer` (offline; the Inference API is not part of the smoke).
- `top_k = 4`.

## Smoke 1 — BLEU question (target = Attention paper, page 8)

Question:

> What BLEU scores does the Transformer achieve on English-to-German and English-to-French translation?

Retrieved (rank order):

| Rank | Source | Page | Score |
| --- | --- | --- | --- |
| 1 | attention_is_all_you_need.pdf | 8 | 0.644 |
| 2 | attention_is_all_you_need.pdf | 9 | 0.573 |
| 3 | attention_is_all_you_need.pdf | 10 | 0.440 |
| 4 | attention_is_all_you_need.pdf | 1 | 0.305 |

The noise PDF (`three_pages.pdf`) does **not** appear in the top-4. Page 8 of the Attention paper still wins top-1 with the same 0.644 it scored under the single-doc run (see [2026-04-25-baseline.md](2026-04-25-baseline.md)). **Pooling didn't drag retrieval quality off.**

Stub citation: `[attention_is_all_you_need.pdf, page 8]`.

## Smoke 2 — Introduction question (target = noise PDF page 1)

Question:

> What does the introduction page say?

Retrieved (rank order):

| Rank | Source | Page | Score |
| --- | --- | --- | --- |
| 1 | three_pages.pdf | 1 | 0.465 |
| 2 | three_pages.pdf | 3 | 0.424 |
| 3 | three_pages.pdf | 2 | 0.345 |
| 4 | attention_is_all_you_need.pdf | 12 | 0.200 |

`three_pages.pdf` page 1 (literally titled "Introduction") wins top-1 against the academic paper. **Cross-doc routing works.**

## Observations

- The pooled-index design (ADR-0008) does what the ADR claims: cross-document cosine scores are directly comparable, and topical relevance routes the right pages to the top regardless of which file they came from.
- Citations now carry the filename — the live demo's right-column source excerpts render `attention_is_all_you_need.pdf — page 8`, not just `Page 8`. Multi-doc results would otherwise be ambiguous.
- The cache key (sorted tuple of resolved paths) means `ask([a, b])` and `ask([b, a])` reuse the same retriever — verified by `test_multi_doc_cache_is_invariant_under_input_order`.

## What is NOT measured here

- Real-LLM answers in the multi-doc setting. Same code path as single-doc; the `[file, page N]` prompt header is the only change.
- Cross-document recall@k. The single-paper gold set does not include cross-document questions, so any multi-doc recall number would be made up.
- Filename-collision behaviour (two uploaded PDFs with the same name). Documented as a v1 limitation in ADR-0008.

## Targets for next iteration

- **Multi-doc gold set.** Even three handcrafted cross-paper questions would let us measure recall@k and faithfulness in the multi-doc setting properly.
- **Persistence by content hash.** The pooled-index rebuild on set change is fine for ≤5 PDFs; anything larger wants caching.
